## Deutsch

**Fassung 931 (17. Oktober 2026)**

### Behoben
- Eine abgelegte App, die mit einem Zusatz in der Adresse startet, öffnet nach einem Update wieder aus dem Speicher des Geräts, statt die Anwendung erneut aus dem Netz zu holen.
- Eine Meldung, die bei offenem Dialog erscheint, etwa ein Fehler beim Export, lag unter dem Weichzeichner und war verschwommen. Sie liegt jetzt über dem Dialog, in jedem Erscheinungsbild und ebenso bei Bannern; bei offenem Dialog steht sie am oberen Rand, damit sie seine Knöpfe nicht verdeckt.
- Die Gültigkeitszeile unter „Reisepass — ausgestellt am“ (Bereich „Mobilität & Reise“) stand eingerückt in der Spalte der Beschriftung. Sie steht jetzt auf derselben linken Kante wie die übrigen Werte; ebenso die Gültigkeitszeile eines Felds in „Finanzen & Zahlungen“ und die Zeilen „Ausdrücklich keine …“ in „Gesundheit“.

### Sicherheit
- VD-SEC-009 (hoch): Behoben in v931. Worum es geht: Vivodepot lässt sich um Erweiterungen ergänzen, das sind Zusatzmodule etwa für Sprache, Rechtsraum oder Vorlagen. In Fassungen vor v917 konnte eine Erweiterung ohne Signatur Texte der Anwendung austauschen, auch amtliche Wortlaute und die Haftungshinweise in der Anwendung und auf jedem PDF. Sie kam über die Einstellungen oder in einer fremden Depot-Datei, die man mit ihrem Passwort öffnete. Angezeigt wurde nur, dass eine ungeprüfte Erweiterung aktiv ist. Was jetzt gilt: Von v917 bis v930 waren solche Erweiterungen gesperrt. Seit v931 wirkt eine Erweiterung, die beim Öffnen einer Depot-Datei mitkommt oder in den Einstellungen eingelesen wird, erst, wenn man sie wählt, und die Anwendung sagt dabei, was sie ändert. Amtliche Wortlaute und Haftungshinweise kann eine Erweiterung ohne Signatur auch dann nicht ersetzen. Betroffen: die vor v917 ausgelieferten Fassungen (zuletzt v857). Was zu tun ist: auf v931 aktualisieren und keine Erweiterung aus einer Datei wählen, die man nicht selbst angelegt hat.

### Hinzugefügt
- Neue Lebenslage „Längere Krankheit“. Sie nennt die Unterlagen, die meist dazugehören (Krankschreibungen, Schreiben der Krankenkasse zum Krankengeld, Arbeitsvertrag, Meldung bei der Agentur für Arbeit, Reha-Antrag und Reha-Bescheid), und unter „Rechtslage …“ drei Hinweise zur Rechtslage in Deutschland zu Krankengeld, Arbeitslosengeld und Reha-Antrag, je mit einem Link auf den Gesetzestext (§ 48 SGB V, § 145 SGB III, § 51 SGB V). Die Hinweise erscheinen, wenn Deutschland als Rechtsraum vorgeschlagen ist.
- Ein QR-Code, der auf eine Webadresse führt, nennt die Adresse lesbar darunter: im Fenster „QR-Code für diese Person“ Host und Pfad, ohne den Teil mit dem Inhalt. Studio: unter dem QR-Code einer Anfrage steht ihre kurze Adresse, und „QR-Code mit Adresse herunterladen“ liefert ein Bild zum Aushängen, auf dem die Adresse mitgedruckt ist.
- Bevor eine Datei aus „Meine Dokumente“ hinausgeht, prüft die Anwendung sie auf aktive Inhalte, etwa ein Skript, eine Aktion, die die Datei von sich aus auslöst, ein Formular, das Daten senden oder laden kann, oder einen Inhalt, der nicht zum Dateityp passt. Bei einer Datei Dritter nennt die Vorschau den Fund; „Original herunterladen“, „Mit Verwahrungsnachweis herunterladen“ und „Sicher weitergeben“ fragen dann vorher „Möchten Sie die Datei so weitergeben?“. Die Datei bleibt unverändert. Ein PDF, das die Anwendung selbst erstellt, wird bei einem solchen Fund nicht ausgegeben, und eine Meldung nennt den Grund.

### Geändert
- Studio: Der Dialog hinter „Fertigstellen und einreichen“ heißt „Einreichen“ und führt in drei Schritten mit je einem Hauptknopf: „Wer reicht ein?“, „Sicherung speichern“, „Einreichung speichern“, danach „E-Mail vorbereiten“. „Sicherung speichern“ erzeugt das Schlüsselpaar und öffnet die Sicherung vor dem Download einmal mit dem Passwort; gelingt das nicht, entsteht keine Datei. Danach steht „Sicherung geprüft, heruntergeladen“; „Ohne Prüfung weiter“ entfällt. Die Prüfergebnisse stehen in einer Zeile „✓ Geprüft (Aufbau, nicht der Inhalt) · Einzelheiten“. Weitere Wege stehen unter „Mehr“, etwa „Ich habe schon eine Schlüsseldatei“ und „Gespeicherte Sicherung prüfen“. Texte im Studio nennen Bedienelemente beim Namen statt mit „oben“ oder „links“.
- Studio: Der Empfangsschlüssel entsteht für genau eine Anfrage, und die Schlüsseldatei gehört zu dieser Anfrage. Ihr Name endet weiter auf „.empfang.vdkey“ und nennt jetzt Vorgang und Datum der Anfrage. Ältere Schlüsseldateien öffnen Antworten wie bisher. Die Lese-App sagt beim Öffnen einer Antwort, an diesem Namen sei die passende Schlüsseldatei zu erkennen. Der Knopf „Empfangs-Schlüsselpaar erstellen“ entfällt; das Paar entsteht beim Erzeugen der Anfrage.

## English

**Version 931 (17 October 2026)**

### Fixed
- An installed app that starts with an addition to its address opens again from the device's storage after an update, instead of fetching the application from the network again.
- A message that appears while a dialog is open, for example an error during export, lay under the blur and was blurred. It now lies above the dialog, in every appearance and likewise for banners; while a dialog is open it stands at the top edge so that it does not cover the dialog's buttons.
- The validity line under “Passport — issued on” (area “Mobility & travel”) stood indented in the column of the label. It now stands on the same left edge as the other values; likewise the validity line of a field in “Finances & payments” and the lines “Explicitly no …” in “Health”.

### Security
- VD-SEC-009 (high): Fixed in v931. What it is about: Vivodepot can be supplemented with extensions, that is add-on modules, for example for language, legal system or templates. In versions before v917 an extension without a signature could replace texts of the application, including official wordings and the liability notices in the application and on every PDF. It came via the settings or in someone else's depot file that one opened with its password. The only thing shown was that an unchecked extension is active. What applies now: from v917 to v930 such extensions were blocked. Since v931 an extension that comes along when a depot file is opened, or that is read in via the settings, takes effect only when one chooses it, and the application says what it changes. Even then an extension without a signature cannot replace official wordings and liability notices. Affected: the versions delivered before v917 (last v857). What to do: update to v931 and choose no extension from a file one did not create oneself.

### Added
- New life situation “Longer illness”. It names the documents that usually belong to it (sick notes, letters from the health insurance fund on sickness benefit, employment contract, registration with the employment agency, rehabilitation application and rehabilitation decision), and under “Legal position: …” three notes on the legal position in Germany on sickness benefit, unemployment benefit and rehabilitation application, each with a link to the text of the law (§ 48 SGB V, § 145 SGB III, § 51 SGB V). The notes appear when Germany is suggested as the legal system.
- A QR code that leads to a web address shows the address readably below it: in the window “QR code for this person” host and path, without the part with the content. Studio: below the QR code of a request stands its short address, and “Download QR code with address” provides an image for posting up, on which the address is printed as well.
- Before a file leaves “My documents”, the application checks it for active content, for example a script, an action that the file triggers by itself, a form that can send or load data, or content that does not match the file type. For a third-party file the preview names the finding; “Download original”, “Download with custody record” and “Share securely” then ask beforehand “Do you want to pass on the file as it is?”. The file remains unchanged. A PDF that the application creates itself is not output in case of such a finding, and a message names the reason.

### Changed
- Studio: the dialog behind “Finish and submit” is called “Submit” and leads through three steps, each with one main button: “Who is submitting?”, “Save backup”, “Save submission”, then “Prepare the e-mail”. “Save backup” creates the key pair and opens the backup once with the password before the download; if that fails, no file is created. Afterwards it says “Backup checked, downloaded”; “Continue without checking” is gone. The check results stand in one line “✓ Checked (structure, not the content) · Details”. Further ways are under “More”, for example “I already have a key file” and “Check saved backup”. Texts in the Studio call controls by their name instead of “above” or “on the left”.
- Studio: the receiving key is created for exactly one request, and the key file belongs to this request. Its name still ends in “.empfang.vdkey” and now names the case and the date of the request. Older key files open replies as before. When a reply is opened, the reader app says that the matching key file can be recognised by this name. The button “Create receiving key pair” is gone; the pair is created when the request is generated.
